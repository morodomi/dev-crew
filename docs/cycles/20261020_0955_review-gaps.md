### Design Approach

#### #265: gate の照合を、最後の REVIEW 節に限る

pre-commit-gate.sh の検査 1 と 2 で、同じ節の取り出しを使う。節は「最後の `### ... - REVIEW` 見出しから、次の `### ` 見出しの手前まで」。awk で最後の見出しの行番号を覚え、そこから次の見出しまでを出す。

- 検査 1: その節に `Phase completed` の行がある
- 検査 2（`which codex` 成功時、今までどおり）: その節に、件数の形の行がある。正規表現は `^- Codex review: (失敗（[^）]*）。adversarial-reviewer で代行: )?直す [0-9]+ / 人間に戻す [0-9]+ / 記録のみ [0-9]+`。Codex が無い環境では検査 2 は走らない（今までどおり）

件数の形まで見るのは、新しい振り分けを行ったことを gate で確かめるため。旧形式の行（`- Codex review: Accept 2, Reject 0` など）は通らなくなる。新しい cycle は v2.20.0 から件数の形で書いており、旧形式で書かれた Cycle doc はすべて phase: DONE なので gate の対象にならない（`for f in docs/cycles/*.md` の phase を実測して確かめる。RED の前に記録する）。

skills/commit/SKILL.md の Pre-COMMIT Gate の bash ブロック（:26-31）を、同じ節の取り出しと同じ正規表現に揃える（skill からは gate script のパスが解決できないので、式を書く。test で gate と同じ正規表現かを確かめる）。見出しの列挙（`REVIEW完了` / `Codex review記録`）は残す（tests/test-doc-consistency.sh:720-732 が workflow.md 側でこの語を見ているため、語を変えない）。

#### #266: commit のまとめ

Step 5 を、REVIEW 節の件数の行から `直す N / 人間に戻す M / 記録のみ K` を出す形に変える。「主な修正」は「直す」の要約、「人間に戻した問い」は人間に戻した指摘、「DISCOVERED」は今までどおり。plan review の結果はまとめに含めない。SKILL.md は 100 行未満を保つ（今 91 行）。

#### #272: 振り分けに 1 項

`## 振り分け` の 3 区分の後に足す: 「今回の diff が入れたものではない、元からある欠陥は直さない。受け入れ条件に関わるなら『人間に戻す』（このサイクルで直すかを問う）、関わらないなら『記録のみ』にし、DISCOVERED に回す」。既存の「P2 は『記録のみ』にせず」（adversarial-review.md:39）に、「ただし、受け入れ条件に関わらない元からある欠陥は、P2 でも『記録のみ』にする」と例外を書き足す。

#### #273: 後片付けと Test List

- `## 振り分け` に、修正役への指示を足す: 「テストを流して出たキャッシュ（`__pycache__` など、修正の前に無かった未追跡ファイル）は消す。足したテストは報告の『確かめたこと』に、ファイル名とテスト名で書く。修正で足したファイル（テスト以外のソースや設定）は『変えたこと』にファイル名を書く」
- steps-codex / steps-subagent / steps-teams の REVIEW 手順:
  - 修正役の起動前と後で、PdM が `git ls-files --others --exclude-standard` を取る。増えた未追跡ファイルのうち、修正役が報告で足したと書いたもの（テストと、修正で足したソースや設定）以外を、COMMIT 前の md の「片付け」に載せる（無ければ節ごと出さない）
  - 記録（手順 3）で、修正役が足したテストを PdM が Test List の DONE に `- [x] TC-R<n>: <テストファイル>::<テスト名>（REVIEW で追加）` として追記する
- レビュー役の一時ディレクトリ: `## 頼み方` の入力に `/tmp/dev-crew-review-<cycle_id>/scratch` を足し、依頼文の「再現用の一時ファイルは /tmp に置く」を「渡した scratch ディレクトリに置く」に変える。agents/adversarial-reviewer.md の 2 か所（:35「`/tmp` に置く…`/tmp` にコピーして実行する」、:43「`mktemp -d` で作り」）を「orchestrate が渡した scratch ディレクトリ。渡されていなければ `mktemp -d`」に変える。steps の手順 1 の `mkdir -p` に scratch を足す。残り物は cycle ごとに 1 つのディレクトリにまとまる（消すのは OS の /tmp の掃除に任せる。hook が再帰削除を止めるため）
